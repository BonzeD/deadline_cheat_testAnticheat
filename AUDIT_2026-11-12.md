# Review and limitations

Scope: static review of the modular client, loader, UI, settings, cleanup, existing mock tests and this change. This is not a complete security certification or a real Roblox/Codex test.

## Changes in this revision
- Aim and ESP master switches start off; other independent feature masters were checked as off. Subordinate filter settings may still be on and take effect only when their master is enabled. Profiles are not loaded automatically, but manual load can activate saved features.
- ESP now deletes its visual objects when switched off in the UI; on activation it rebuilds them. Periodic ESP and team scans are protected separately against errors. This improves recovery but does not establish the cause of the reported failure in a real place.
- Crosshair line positions and rotations are computed explicitly rather than relying on parent frame rotation. Actual GUI rendering remains unverified.
- R6/R15 skeleton uses centres of named parts, skips missing parts and cleans its lines on removal. It is approximate, does not cover custom rigs, and consumes extra GUI objects.
- UI language switch added; main labels are translated, while some descriptions and dynamic errors still appear in English.

## Outstanding risks
- The network loader executes source fetched from the mutable public `main` branch. Anyone with write access, a compromised account or changed upstream code can change what runs. Review and pin a trusted revision when reproducibility matters; a public client is not secret.
- Executor APIs, game models, camera behaviour, UI layering and performance differ. Mocks do not execute Roblox physics or render the actual GUI. This review cannot verify executor safety, game compatibility or anti-cheat bypasses.
- Experimental metamethod hooks can remain installed but inactive until the game session ends; multiple scripts may interact. The test-only bypass modes use an explicit place allowlist; they are not proof of defeating a server-side check.
- Highlight count, 2D lines and skeletons can reduce FPS in populated places. Configurable scanning and refresh limits are available; test the target device and place.
- Local profiles contain settings and bindings, and are manually loaded. File functions and paths vary by executor. Profile names and values are validated, but no guarantee is made for a compromised executor.

Run `python3 tests/run_all.py` for isolated Lua 5.4 mocks and follow the real-place checklist in `tests/README.md`.
